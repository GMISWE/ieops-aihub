artifact viewer — 长文档可读性重构

把 /ui/artifacts/<id>/html 从一面"文字墙"重构成可扫读的长文档阅读器：目录大纲、章节折叠、结构化 chrome、语义图标、diagram-as-code、批注收纳。单一真相仍是 markdown，不动主逻辑。

Summary
消费端（aihub）从 skill 已经在吐的 content + structured_payload 渲染出本页全部结构化区块——所以历史 memory 不用重生成就能升级外观。
Design decisions
单一真相 = markdown content；rendered_html 降级为快照缓存
备选：存双份 / 改用 HTML 源
密度高、可 embedding、消除 content↔html 漂移
图走 D2 服务端渲染成内联 SVG
备选：mermaid.js 客户端渲染
no-build + 确定性字节 + 守住 /share 严格 CSP（无脚本）
批注收纳为行内 marker + 浮层，不再常驻右边距 rail
备选：保留 300px 批注栏
正文加宽，又保住批注与原文的空间对应
窄生产契约：skill 只吐语义，aihub 包揽表现
备选：让 skill 直接生成 HTML
改 aihub 即可，所有历史 memory 免费升级
Acceptance criteria
  • 右栏 TOC 复用现成 ExtractHeadings()，可跳转 + scroll-spy 高亮
  • H2/H3 章节可折叠（服务端 <details>，零 JS、/share 可用）
  • golden-byte 测试断言 /v1+/share 输出逐字节不变
  • renderChrome 对 payload 容错（缺字段降级、多字段忽略）
  • 正文加宽至 ≥860px + slim 右栏 + Share 移至右上
Non-goals
  • 不把存储格式换成 HTML
  • 不引前端框架 / 打包 / npm（保持 SSR + HTMX + vanilla）
  • 不动冻结的 annotator.js / style.css
· 长文档：扫大纲、按需展开
背景

当前 memory 有两份内容：content（markdown，信息密度高、天生适合存 AI 记忆）和 rendered_html（表达力强但密度低）。问题是长文档一长基本没法读，信息量糊一脸1。

关键认知：读者看到的永远是渲染后的页面，不是 markdown 源。所以可读性是 渲染器 + CSS + 信息架构 决定的，跟"源用什么格式存"无关。换成 HTML 源既不解决可读性，又赔上密度与 /share 的安全。

架构：生产端 / 消费端分层

skill 只吐语义（markdown + 结构化 payload），aihub 包揽表现。下面这张图就是用 ```d2 写在正文里、服务端渲染成内联 SVG 的——源是几行文本，AI 可写可 diff。

渲染管线

表现力靠扩展 markdown + 渲染层，而不是换格式：

  • 语义图标：从 Lucide 子集内联 SVG，按含义映射（本页所有图标即是）。
  • diagram-as-code：```d2 / ```dot → goldmark AST 扩展 → 内联 SVG。
  • 结构化 chrome：decisions / AC / findings 从 structured_payload 走模板，而非烤进 HTML。
  • 章节折叠 + TOC：服务端把 H2 包进 <details>，右栏大纲接 ExtractHeadings。
风险与守护

最脆的点是 rendered_html 退役不破 /share 老链接。取舍：publish 快照 + 老链接 grandfather + golden-byte 测试，不赌"确定性渲染能逐字节复刻历史"2。批注收纳要动 annot.js（高风险、需浏览器验），单独隔离到最后阶段。

这个原型体现了哪些决策

  • 正文加宽：doc ≤880px（原 720）；右栏收窄到 256px D6
  • 批注收纳：高亮 + 行内 marker，点开浮层显示，不再常驻右边距栏 D6
  • 右栏 = TOC（scroll-spy）+ Version history（supersedes 版本链，review 钉在版本上）+ Details(meta) + Comments
  • 结构化 chrome：Summary / Decisions / AC / Non-goals 从 structured_payload 渲染，不在散文里
  • 语义图标：内联 SVG（Lucide 子集），按含义映射，零 JS、CSP 安全
  • diagram-as-code：架构图是"```d2 → 服务端 SVG"的示意
  • 章节折叠：H2 → <details>；上方"展开/折叠全部"
  • Share 移到右上；深浅色用真实 #129 tokens + Geist 字体

  • 正文宽度、行宽、留白舒服吗？
  • 批注 marker + 浮层这个交互，比常驻右栏好用吗？
  • chrome 卡片该放正文上方（现在）还是折进可展开？
  • 图标用得是否克制、不花哨？
  • 右栏三块（TOC/meta/comments）顺序与取舍？
