# Repo detail: where `main_modules` / `change_scenarios` / `tech_stack` live

`polyforge init` renders a `## Workspace` managed block into the workspace-root
`CLAUDE.md`. That block is injected at context position 0, re-read on **every** request,
and compaction cannot drop it — so it carries only what routing needs at a glance:

```
### <project>
<project description>
> Repo detail (stack / modules / changes): `.polyforge/repo-map/<project>.md`

- **<repo>**: <one-line positioning>
```

The four-field detail (`positioning` / `tech_stack` / `main_modules` /
`change_scenarios`, plus the `generated:` freshness stamp) lives in
`.polyforge/repo-map/<project>.md`, one file per project. Measured on the gmi-ws
workspace, moving it out took the block from 34,606 B to ~6.3 KB.

## How to use it

1. Route to a project/repo on the one-line `positioning` in the block.
2. `Read .polyforge/repo-map/<project>.md` — **only** the project you routed to, not all
   of them. That is the whole point of the split.
3. For code *inside* the repo, prefer `codegraph_*` / `Grep` over the map: the map is a
   snapshot regenerated by `polyforge init` and can lag the repo, while those are current.

## When the pointer line is not there

The pointer is written by the same code that writes the map file, so wherever you see the
pointer the file exists. If a block has **no** pointer line, it predates this split and
the detail is inlined under each repo as two-space-indented `  - stack:` / `  - modules:`
/ `  - changes:` bullets — read it from context, no file read needed.

If a block has no pointer line *and* no inline bullets, or the pointer names a file that
is not there, the map is missing: say so and run `polyforge init` (its `doctor` check 6,
`claude_md`, reports exactly this). Do not guess a repo's internals from its positioning.

## Regeneration

`polyforge init` rewrites every `*.md` under `.polyforge/repo-map/` and **deletes** any
that no longer corresponds to a project. Nothing hand-written survives there. The maps are
written before the block is slimmed, so a failed init leaves the workspace unchanged
rather than block-slimmed-with-no-detail.
